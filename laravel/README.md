# کیت لاراول: قالب جدید sepahanfelez.ir

این پوشه فقط **قالب** است: ظاهر سایت و منطق نمایش.
هر کلمه، عدد، عکس، قیمت و فیلد سئو که در سایت دیده می‌شود، مثل قالب قبلی از **پنل مدیریت** (`/admin`) خوانده می‌شود.
در این کیت هیچ متن، عکس محصول یا قیمتی نیست.

- **پنل مدیریت و بک‌اند** تغییری نمی‌کنند. همان فرم‌ها و همان جدول‌ها می‌مانند.
- **هیچ کنترلری ویرایش نمی‌شود.** کنترلرها مثل قبل `view('site.home')` برمی‌گردانند و نسخه‌ی جدید همان ویو رندر می‌شود.
- **خاموش کردن:** با `REDESIGN_ENABLED=false` سایت بلافاصله همان قالب قبلی است.

## هر بخش صفحه از کجای پنل می‌آید

| بخش سایت | پنل مدیریت |
|---|---|
| تلفن، ایمیل، ساعت کاری، نشانی‌ها، متن زیر عنوان فوتر | تنظیمات ← اطلاعات تماس |
| آیکون‌ها و لینک واتساپ، تلگرام و اینستاگرام | تنظیمات ← شبکه‌های اجتماعی (فقط موارد فعال) |
| نام فروشگاه در سرصفحه، favicon | تنظیمات عمومی |
| اسلایدهای صفحه‌ی اصلی (متن «alt» روی عکس نوشته می‌شود) | تنظیمات ← اسلایدر |
| عنوان و توضیح سئوی صفحه‌ی اصلی، متن و عکس «درباره» در صفحه‌ی اصلی، دو بنر پایین | تنظیمات صفحه اصلی |
| عنوان و توضیح سئوی صفحه‌ی قیمت | تنظیمات صفحه اصلی (price_…) |
| ویدئوهای کارخانه در صفحه‌ی اصلی | گالری ویدئو |
| صفحه‌ی «درباره ما» (متن، عکس، ویدئو) | درباره ما |
| دسته‌ها: عنوان، ترتیب، عکس، ویدئو، برچسب‌ها | دسته‌بندی ← ویرایش |
| زیرعنوان دسته | دسته‌بندی ← توضیح متا (فرم دسته فیلد «معرفی» ندارد) |
| راهنما و پرسش‌های دسته | دسته‌بندی ← متن. هر تیتر **H2** یک بخش بازشونده است. H2ای که با «پرسش…» شروع شود و پرسش‌هایش **H3** باشند، بخش «پرسش‌های پرتکرار» و داده‌ی FAQ گوگل می‌شود |
| ستون‌های جدول قیمت | دسته ← ستون‌های جدول (ترتیب) |
| ویژگی‌ها / کاربردها | دسته ← ویژگی‌ها / کاربردها |
| محصول: عنوان، قیمت، واحد، مشخصات، فعال/غیرفعال | محصول ← ویرایش |
| صفحه‌ی اختصاصی محصول، عکس، توضیحات، سئو | محصول ← محتوا. **بدون اسلاگ، محصول صفحه ندارد** و فقط در جدول دسته دیده می‌شود |
| نمودار قیمت، «نوسان»، تاریخ بروزرسانی | تاریخچه‌ی قیمت / ایمپورت اکسل (جدول `prices`) |
| مجله، مقاله‌های مرتبط | مقالات، دسته‌بندی مقالات، برچسب‌ها |
| دیدگاه‌ها | نظرات ← دیدگاه دسته‌بندی‌ها (تأیید و پاسخ) |
| پیام فرم تماس، تیکت، ثبت‌نام | همان بخش‌های قبلی پنل |

**تنها تغییر ظاهری در پنل مدیریت:** لوگوی بالای منوی کناری. لوگوی قبلی (عکس بلند ۲۱۶×۴۰۴) از نوار بالای منو بیرون می‌زد، روی کادر «جستجو در منو» می‌افتاد و بریده می‌شد. کیت فقط `partials.brand-mark` را جایگزین می‌کند و نشان مربعی و نام فروشگاه را هم‌اندازه‌ی نوار نمایش می‌دهد.

هر بخشی که در پنل خالی باشد، در صفحه نمایش داده نمی‌شود. متن جایگزین ساختگی نمایش داده نمی‌شود.

## نصب (برای «لایو کن»)

1. **بکاپ کامل** از فایل‌ها و دیتابیس (cPanel → Backup Wizard).
2. **فایل‌ها:** محتوای این پوشه را (به‌جز همین README) در ریشه‌ی مخزن Ahanamn کپی کنید. همه‌ی فایل‌ها تازه‌اند و هیچ فایل موجودی بازنویسی نمی‌شود.
3. **یک خط** در `config/app.php`، بعد از `RouteServiceProvider`:
   ```php
   App\Providers\RedesignServiceProvider::class,
   ```
4. push روی `main`. CI/CD فایل‌ها را آپلود می‌کند. تا قدم ۶ سایت عوض نمی‌شود، چون پیش‌فرض خاموش است.
5. **محتوای تأییدشده‌ی پروتوتایپ را در پنل وارد کنید** (یک بار، از طریق فرم‌های خود پنل):
   ```bash
   python3 tools/apply_pack.py login --mobile 09…   # کد پیامکی را می‌پرسد
   python3 tools/apply_pack.py plan                  # فقط نشان می‌دهد چه چیزی عوض می‌شود
   python3 tools/apply_pack.py apply                 # اعمال، با بکاپ از مقادیر قبلی
   ```
6. در `.env` سرور (از File Manager سی‌پنل): `REDESIGN_ENABLED=true`.

**برگشت:** `REDESIGN_ENABLED=false`. متن‌های قبلی پنل در `migration/backup/<زمان>/` ذخیره شده‌اند.

## مسیرهایی که کیت اضافه می‌کند

| مسیر | کار |
|---|---|
| `GET /rd/search-index.json` | فهرست جست‌وجوی سراسری از دیتابیس (بدون سشن، کش‌پذیر) |
| `GET /rd/chart/product/{id}`، `GET /rd/chart/category/{id}` | تاریخچه‌ی قیمت از جدول `prices`. به cron نیاز ندارد |
| `GET /cart` | ۳۰۱ به `/price`. سبد خرید در قالب جدید نیست و سفارش تلفنی است |

کش: کاتالوگ و تنظیمات ۱۰ دقیقه کش می‌شوند و با **هر ذخیره در پنل** فوراً پاک می‌شوند.

## آزمایش

همه‌ی این مراحل روی یک کپی از Ahanamn با دیتابیس آزمایشی انجام شد (`tools/lab/`):

- دیتابیس دقیقاً در وضعیت فعلی سایت زنده: محصولات بدون اسلاگ و عکس، متن‌های قدیمی. همه‌ی صفحه‌ها بدون خطا بودند و لینک شکسته‌ای به محصول نبود.
- `tools/apply_pack.py apply` روی **پنل مدیریتِ همان کپی** اجرا شد و همه‌ی فرم‌ها ذخیره شدند. بعد از آن همه‌ی صفحه‌ها کد ۲۰۰ دادند.
- پروتوتایپ نمایشی (`sepahanfelez.lenzit.ir`) خروجی همین کپی است (`tools/export_static.py`)، پس دقیقاً همان چیزی است که بعد از لایو شدن دیده می‌شود.
