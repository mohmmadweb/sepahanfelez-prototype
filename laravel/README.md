# کیت لاراول — تعویض کامل فرانت sepahanfelez.ir با پروتوتایپ

این پوشه همان طراحی پروتوتایپ است که روی دیتابیس واقعی سایت (`mohammad-kasiri/Ahanamn`، لاراول ۸) اجرا می‌شود.
ساختارش عین ریشه‌ی پروژه‌ی لاراول است: هر فایل را با همین مسیر در ریشه‌ی لاراول کپی کنید.

همه‌ی صفحه‌های عمومی عوض می‌شوند: خانه، قیمت لحظه‌ای، فهرست دسته‌ها، دسته، محصول، مجله (فهرست، دسته، مقاله با دیدگاه)، درباره، تماس، نویسنده.
ورود و ثبت‌نام پیامکی، کل ناحیه‌ی کاربری (مشخصات، سفارش‌های پیشین، نشانی‌ها، تیکت، راهنما) و صفحه‌های خطا (۴۰۴، ۴۱۰، ۴۱۹، ۴۲۹، ۵۰۰، ۵۰۳) هم عوض می‌شوند.
**پنل ادمین (`/admin`) هیچ تغییری نمی‌کند.**

**سبد خرید حذف شده است.** سفارش تلفنی ثبت می‌شود. `GET /cart` با کد ۳۰۱ به `/price` می‌رود و دکمه‌ی «افزودن به سبد» هیچ‌جا نیست.

---

## اصل کار: هیچ کنترلری ویرایش نمی‌شود

کنترلرهای فعلی همچنان `view('site.home')` یا `view('auth.login')` برمی‌گردانند.
`RedesignServiceProvider` پوشه‌ی `resources/views/redesign` را **جلوی** مسیر ویوها می‌گذارد.
ویویی که همنامش آنجا باشد، جای قالب قدیمی رندر می‌شود. هر ویویی که آنجا نیست، مثل کل ادمین، همان قدیمی می‌ماند.

| منبع | چه چیزی |
|---|---|
| دیتابیس | هر عدد: دسته، محصول، قیمت، مشخصات فنی، تاریخچه‌ی قیمت، مقاله، دیدگاه، کاربر، تیکت، سفارش |
| `resources/redesign/content.php` | متن‌های تحریری پروتوتایپ: معرفی دسته‌ها، راهنما، پرسش‌ها، اعتماد، درباره، واحد فروش، کرایه. **ساخته‌شده** از `build/content.py` پروتوتایپ |
| `config/redesign.php` | فقط کلیدها (روشن/خاموش، ارقام فارسی، نمودار نمونه، دیدگاه نمونه) |

**برگشت:** با `REDESIGN_ENABLED=false` در `.env`، پرووایدر هیچ کاری نمی‌کند و سایت عیناً همان قبلی است. دیپلوی دیگری لازم نیست.

## نصب (۴ قدم)

1. **کپی فایل‌ها** در ریشه‌ی لاراول (همه فایل تازه‌اند و هیچ فایل موجودی بازنویسی نمی‌شود):

   | از این پوشه | چیست |
   |---|---|
   | `app/Providers/RedesignServiceProvider.php` | تنها نقطه‌ی اتصال |
   | `app/Support/Rd.php` | کمکی‌های قالب: تاریخ شمسی، اعداد، JSON-LD. ترجمه‌ی `common.py` و `schema.py` |
   | `app/Support/Redesign.php` | لایه‌ی داده: کاتالوگ با ۵ کوئری و کش ۱۰ دقیقه، تاریخچه‌ی قیمت، جست‌وجو، مقاله‌ها |
   | `app/Support/RedesignAnalysis.php` | ترجمه‌ی خط‌به‌خط `analysis.py`: قیمت قابل‌مقایسه، نکات خرید، ماشین‌حساب |
   | `app/Http/Middleware/RedesignFaDigits.php` | ارقام فارسی در متن صفحه‌ها (غیر از ادمین) |
   | `app/Http/Controllers/RedesignController.php` | سه اندپوینت JSON و ریدایرکت سبد خرید |
   | `config/redesign.php` | کلیدها |
   | `resources/redesign/content.php` | متن‌ها (ساخته‌شده) |
   | `resources/views/redesign/**` | همه‌ی قالب‌ها |
   | `public_html/rd/**` | CSS، JS، فونت استعداد، لوگو، عکس محصولات و اسلایدها، ویدئوی کارخانه |

2. **یک خط** در `config/app.php`، در فهرست `providers` و بعد از `RouteServiceProvider`:
   ```php
   App\Providers\RedesignServiceProvider::class,
   ```
3. **یک خط** در `.env` سرور:
   ```
   REDESIGN_ENABLED=true
   ```
4. **اختیاری:** فایل `database/sql/2026_09_22_redesign_columns.sql` را در phpMyAdmin اجرا کنید (یک بار، و اجرای دوباره‌اش بی‌خطر است).
   این فایل امتیاز ستاره‌ای دیدگاه، وزن و متراژ عددی محصول، و جدول‌های کارشناس فروش و نرخ کرایه را اضافه می‌کند.
   بدون آن هم همه‌چیز کار می‌کند: ستاره‌ها پنهان می‌مانند و وزن از متن مشخصات خوانده می‌شود.

`npm`، `composer` و مایگریشن لازم نیست. هیچ پکیج تازه‌ای هم اضافه نمی‌شود.
با CI/CD فعلی (push روی `main` و آپلود با API سی‌پنل) فقط فایل‌های بالا آپلود می‌شوند.
`.env` سرور را دیپلوی دست نمی‌زند، پس قدم ۳ را یک بار دستی در File Manager سی‌پنل انجام دهید.

## چه چیزی به برنامه اضافه می‌شود

| مسیر | کار |
|---|---|
| `GET /rd/search-index.json` | فهرست جست‌وجوی سراسری (همان ساختار پروتوتایپ). بدون سشن و کش‌پذیر |
| `GET /rd/chart/product/{id}` | تاریخچه‌ی قیمت یک کالا از جدول `prices` |
| `GET /rd/chart/category/{id}` | میانگین قیمت یک دسته در طول زمان |
| `GET /cart` | ۳۰۱ به `/price` (با `redirect_cart` در کانفیگ خاموش می‌شود) |

**نمودار دیگر به cron نیاز ندارد.** داده از جدول `prices` می‌آید که ایمپورت اکسل پر می‌کند، نه از `chart_price` (که `price:update` می‌نوشت و هیچ‌وقت زمان‌بندی نشده بود).
هر ثبت قیمت یک «پله» است. اگر `chart_price` داده‌ای داشته باشد، روزهای خالی را پر می‌کند.

## فشار روی هاست

- کاتالوگ کامل (۷۰ کالا با مشخصات و آخرین قیمت) با ۵ کوئری ساخته و ۱۰ دقیقه کش می‌شود. ذخیره‌ی محصول، قیمت، دسته یا مقاله کش را فوراً پاک می‌کند.
- در آزمایشگاه، صفحه‌ی `/price` با ۶ کوئری و صفحه‌ی خانه (با کش گرم) با ۰ کوئری رندر شد.
- بررسی وجود ستون و جدول (`information_schema`) یک ساعت کش می‌شود.
- JS و CSS تازه بدون jQuery و Bootstrap است (کل JS حدود ۶۷ کیلوبایت).
- ویدئوهای کارخانه ۲۷ مگابایت‌اند و فقط با کلیک بار می‌شوند (`preload="none"`). اگر ترافیک هاست محدود است، آن‌ها را جای دیگری بگذارید و نشانی را در `resources/redesign/content.php` (کلید `plants`) عوض کنید.

## متن‌ها را کجا عوض کنیم

**`resources/redesign/content.php` را دستی ویرایش نکنید.** در پروتوتایپ `build/content.py` را عوض کنید و `python3 build/gen.py` را اجرا کنید.
این کار هم صفحه‌های پروتوتایپ را می‌سازد و هم `content.php` و `public_html/rd/` را در همین کیت بروز می‌کند (`tools/build_kit.py`).
دسته‌ای که ادمین تازه بسازد و در `content.py` متنی نداشته باشد، خودکار با فیلدهای خود دیتابیس (توضیح متا، intro، body) نمایش داده می‌شود.

## آزمایش پیش از لایو

این کیت روی یک کپی از Ahanamn با PHP 7.4 (نسخه‌ی قفل‌شده‌ی `composer.lock`) و دیتابیس SQLite آزمایش شد.
دیتابیس از کاتالوگ و مقاله‌های خود پروتوتایپ پر شده بود (`tools/lab/seed.php`).

- ۱۲۸ نشانیِ فهرست جست‌وجو و همه‌ی صفحه‌های ناحیه‌ی کاربری: ۲۰۰
- فرم تماس (خطای اعتبارسنجی و ثبت موفق)، ثبت دیدگاه، تیکت تازه، پیام تیکت، نشانی تازه، خروج: کار می‌کنند
- `php artisan view:cache` (همه‌ی ۲۰۴ قالب، شامل ادمین): موفق
- بررسی‌های CI خود Ahanamn (`frontend-check.php` با ۶۱ بررسی، `brand-scrub-check.php` با ۲۵۳ بررسی): همه قبول
- با `REDESIGN_ENABLED=false` سایت دقیقاً قالب قبلی را نشان می‌دهد

روش ساخت همین آزمایشگاه در `../tools/lab/README.md` آمده است.

**یک باگ قبلی بک‌اند که پیدا شد:** ستون `addresses.postal_code` در دیتابیس NOT NULL است، ولی `AddressController` آن را `nullable` اعتبارسنجی می‌کند.
نشانیِ بدون کد پستی خطای ۵۰۰ می‌داد. فرم تازه کد پستی را اجباری کرده تا این خطا پیش نیاید. خود کنترلر دست نخورده است.

## بروزرسانی قیمت از اکسل

پروتوتایپ دقیقاً همان قرارداد `app/Excel` بک‌اند فعلی را رعایت می‌کند،
پس همان فایل اکسلی که امروز برای سایت زنده می‌سازید، بدون تغییر کار
می‌کند.

**قرارداد ستون‌ها** (از `ProductsExport` و `ProductsImport`):

| ستون | محتوا | وارد می‌شود؟ |
|---|---|---|
| ۰ | شناسه‌ی محصول (`id`) | بله — کلید تطبیق |
| ۱ | عنوان (`title`) | خیر — فقط برای خواندن آدم |
| ۲ | قیمت (`price`) به ریال | بله |

بدون سطر عنوان. بک‌اند با `ToCollection` از سطر اول داده می‌خواند.

**منطق، عیناً مثل `updateProductAndCreatePrice`:**

- قیمت تازه با قیمت فعلی فرق دارد و عددِ مثبت است → یک رکورد در
  `prices` ساخته می‌شود (`first_price` قیمت قبلی، `second_price` قیمت
  تازه، `price_at` اکنون) و `products.price` بروز می‌شود.
- فرقی ندارد → فقط `price_at` آخرین رکورد و `updated_at` محصول تازه
  می‌شوند. یعنی «امروز هم همین قیمت» ثبت می‌شود و نمودار روزهای ثابت
  را هم می‌بیند.
- خالی، صفر یا غیرعددی → رد می‌شود، بدون خطا.

**در پروتوتایپ:**

```bash
python3 tools/prices_excel.py export prices.xlsx        # گرفتن قالب
python3 tools/prices_excel.py import prices.xlsx --dry  # گزارش بدون تغییر
python3 tools/prices_excel.py import prices.xlsx        # اعمال
python3 build/gen.py                                    # ساخت دوباره‌ی صفحه‌ها
```

تاریخچه در `build/price-history.json` با همان ساختار جدول `prices`
ذخیره می‌شود، پس وقتی بک‌اند وصل شد می‌توان آن را مستقیم منتقل کرد.

**یک نکته‌ی مهم:** تا وقتی id واقعی پایگاه‌داده در دست نیست، شناسه در
پروتوتایپ به شکل `کلید-دسته:ردیف` ساخته می‌شود. بعد از اتصال، کافی است
ستون `id` واقعی در `catalog.json` نوشته شود و بقیه‌ی زنجیره دست‌نخورده
کار می‌کند.
