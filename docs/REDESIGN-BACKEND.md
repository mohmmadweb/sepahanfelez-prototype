# اتصال دمو به بک‌اند لاراول

**مخزن بک‌اند:** `github.com/mohammad-kasiri/Ahanamn` (کلون محلی: `~/projects/Ahanamn`)
**کیت اتصال:** پوشه‌ی `laravel/` همین مخزن
**تاریخ:** ۳۱ شهریور ۱۴۰۵

> مخزن بک‌اند در این مرحله **دست‌نخورده** است. هر فایلی که لازم بود، اینجا و
> با ساختار مقصد نوشته شده تا هر وقت خواستید کپی شود.

---

## ۱. اصل کار

دمو امروز ایستاست و داده‌اش ماک است. بعد از اتصال:

- **ورود داده، همان `/admin` امروز است.** هیچ پنل تازه‌ای ساخته نمی‌شود.
- **هر چیزی که دیتابیس دارد، از دیتابیس خوانده می‌شود.** فهرست کامل در بخش ۳.
- **هر چیزی که اسکیما ندارد، در `config/redesign.php` است** و کنارش نوشته
  شده جای واقعی‌اش کدام جدول است (بخش ۴).
- **کلید برگشت:** `REDESIGN_ENABLED=false` → قالب قبلی برمی‌گردد، بدون
  دیپلوی دیگر. هر دو مجموعه قالب در مخزن می‌مانند.

## ۳. آنچه از همین حالا از دیتابیس می‌آید

هیچ‌کدام کد تازه لازم ندارند؛ همان جدول و همان صفحه‌ی پنل.

| روی صفحه | جدول / ستون | پنل |
|---|---|---|
| نام، عنوان، متن معرفی و بدنه‌ی دسته | `categories.title/intro/body/meta_*` | دسته‌بندی‌ها |
| عکس و آیکون دسته | `categories.image/icon` | دسته‌بندی‌ها |
| نام، قیمت، واحد، اسلاگ، ترتیب محصول | `products.*` | محصولات |
| توضیحات محصول (متن بلند) | `products.description` | محصول → محتوا |
| عکس محصول | `products.image` | محصول → محتوا |
| ستون‌های جدول و ترتیبشان | `category_spec.sort` + `specs`/`values` | ستون‌های جدول |
| قیمت روز و «نوسان» | `products.price` + `prices.first/second_price` | اکسل یا ویرایش محصول |
| مهر «آخرین بروزرسانی» | `MAX(prices.price_at)` | خودکار |
| نمودار قیمت محصول | `chart_price` → `/product/{id}/{tf}` | دستور `price:update` |
| نمودار میانگین دسته | `daily_avg_price` → `/category/chart/{id}/{tf}` | همان |
| ویژگی‌ها و کاربردهای دسته | `features` / `usages` | دسته → ویژگی/کاربرد |
| دیدگاه‌ها و پاسخ کارشناس | `product_comments` | نظرات دسته‌بندی |
| مقاله‌ها، دسته‌ی مقاله، تصویر، بازدید | `articles` / `article_categories` | مقالات |
| ربط مقاله ↔ دسته (دو طرفه) | `tags` + `taggables` | برچسب‌ها |
| اسلایدر صفحه‌ی اصلی | `sliders` | تنظیمات → اسلایدر |
| متن و عکس «درباره» صفحه‌ی اصلی | `home_settings` | تنظیمات صفحه اصلی |
| عنوان و متای صفحه‌ی قیمت | `home_settings.price_*` | تنظیمات صفحه اصلی |
| تلفن، ایمیل، ساعت کاری، نشانی‌ها | `information` | اطلاعات |
| شبکه‌های اجتماعی | `socials` + `config/brand.php` | شبکه‌های اجتماعی |
| سبد خرید، سفارش، ورود، پنل کاربر | `carts`/`orders`/`users` | سفارش‌ها، کاربران |
| اسکیما، کنونیکال، نقشه‌ی سایت | `App\Support\Schema` + `Sitemap` | خودکار |

**نتیجه:** هر ۱۲۲ صفحه‌ی دمو از همین جدول‌ها پر می‌شود. چیزی که در دمو
«۷۰ نوع کالا» است، بعد از اتصال هر تعدادی است که در پنل فعال باشد.

## ۴. آنچه هنوز ماک است و چه چیزی واقعی‌اش می‌کند

| مورد | چرا ماک است | چه چیزی لازم دارد | بدون آن چه می‌شود |
|---|---|---|---|
| کارشناسان فروش | جدولی برای آن نیست | `sales_reps` + `category_sales_rep` | از `config/redesign.php` خوانده می‌شود |
| نرخ کرایه‌ی حمل | جدولی برای آن نیست | `freight_rates` | نرخ نمونه، با برچسب «برآورد» روی صفحه |
| امتیاز ستاره‌ای | `product_comments` ستون `rating` ندارد | یک ستون | ستاره‌ها حذف می‌شوند، متن دیدگاه می‌ماند |
| وزن عددی هر واحد | وزن فقط متن است («۲۲ کیلوگرم») | `products.weight_per_unit` | از متن مشخصات خوانده می‌شود (دقت کمتر) |
| نشان «بازبینی» | فیلدی برای آن نیست | `products.needs_review` | نشان نمایش داده نمی‌شود |
| دیدگاه نمونه | تا وقتی دیدگاه واقعی نیست | — | با اولین دیدگاه تأییدشده خودبه‌خود کنار می‌رود |

همه در یک فایل: `laravel/database/sql/2026_09_22_redesign_columns.sql`.
اجرایش اختیاری است و سایت بدون آن هم کار می‌کند.

### چرا ستون عددی وزن مهم است
ماشین‌حساب باید وزن را در تعداد ضرب کند. امروز وزن در `values.title` به شکل
متن است و در این صنعت «/» جداکنندهٔ اعشار است: «1/200» یعنی ۱٫۲ کیلوگرم، نه
یک دویستم. کد این را درست می‌خواند، ولی یک ستون عددی اصلاً نمی‌تواند غلط
خوانده شود.

## ۵. نمودار: داده‌ی واقعی، نه نمایشی

`redesign.js` اول اندپوینت واقعی را صدا می‌زند
(`/product/{id}/{timeframe}` و `/category/chart/{id}/{timeframe}` که
`Site\PriceController` از قبل سرو می‌کند و روی `chart_price` و
`daily_avg_price` نشسته‌اند).

- **دو نقطه یا بیشتر برگشت** → همان رسم می‌شود و زیرش می‌نویسد
  «برگرفته از تاریخچه‌ی واقعی ثبت قیمت‌ها».
- **کمتر از دو نقطه** (کالای تازه) → یا سری نمایشی بین «آخرین قیمت ثبت‌شده»
  و «قیمت روز» کشیده می‌شود و صریحاً نوشته می‌شود نمایشی است، یا با
  `REDESIGN_CHART_SAMPLE=false` پیام «هنوز تاریخچه‌ی کافی ثبت نشده» می‌آید.

هیچ حالتی نیست که عدد ساختگی به‌جای داده‌ی واقعی جا بزند.

> **یک نکته‌ی عملیاتی:** دستور `price:update` در `app/Console/Kernel.php`
> ثبت **نشده** و این هاست cron ندارد. تا وقتی این حل نشود، `chart_price` پر
> نمی‌شود و نمودارها روی حالت «تاریخچه‌ی کافی نیست» می‌مانند. سه راه در
> `DEPLOYMENT.md` آمده (cPanel cron، GitHub Actions، دکمه‌ی دستی در پنل).

---

## ۶. ترتیب اجرا

1. فایل‌های بخش ۲ را کپی کنید.
2. پچ‌های `laravel/patches/` را اعمال کنید.
3. `npm run prod`.
4. (اختیاری) SQL بخش ۴ را در phpMyAdmin اجرا کنید.
5. `REDESIGN_ENABLED=true` در `.env`.
6. سه صفحه را باز کنید: یک دسته، یک محصول، `/price`.

**برگشت:** `REDESIGN_ENABLED=false`.

---

## ۷. آنچه این کیت عمداً انجام نمی‌دهد

- **دست‌زدن به پنل ادمین.** هیچ ویوی `admin/*` تغییر نمی‌کند.
- **دست‌زدن به سبد خرید، ورود و پنل کاربر.** همه سالم‌اند و دکمه‌ی «افزودن به
  لیست سفارش» در صفحه‌ی محصول جدید هم هست.
- **حذف قالب‌های قبلی.** هر دو کنار هم می‌مانند.
- **migration.** روی این هاست اجرا نمی‌شود؛ به‌جایش فایل SQL.
- **تغییر اسکیمای موجود.** فقط ستون و جدول تازه، همه با چک وجود.
